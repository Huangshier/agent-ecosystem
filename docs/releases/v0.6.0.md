# Agent Ecosystem v0.6.0

`v0.6.0` establishes a new runtime lifecycle baseline. Ordinary installs are
copy-first, updates are manifest-aware and conservative, and agent-specific
skill discovery is an explicit step instead of an installation side effect.

## Who should update

- Existing users who want protected incremental runtime refresh, explicit
  install conflict reports, or the new agent-specific skill bridge.
- Users of the candidate intake, directory index diagnostics, or experience
  search workflows added after `v0.5.2`.
- New users should start directly from `v0.6.0`.

## Required upgrade actions

### Runtime action

From the checked-out `v0.6.0` tag, run:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install.ps1 -Profile recommended
```

Schema-2 runtimes refresh incrementally. A schema-1 copy runtime cannot prove a
per-file installed baseline: if managed content differs, the default command
reports a conflict and leaves schema 1 in place. Review or back up local runtime
changes, then explicitly complete migration when appropriate:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install.ps1 -Profile recommended -ReplaceManaged
```

`-ReplaceManaged` replaces managed content while preserving unknown files.
`-Force` remains only as a deprecated compatibility alias.

### Project refresh action

Project memory created from `v0.4.2` or later remains structurally compatible.
After updating the runtime, run read-only checks before deciding whether a
project refresh is useful:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File <runtime>\skills\project-bootstrap\scripts\check_hub_lock.ps1 -ProjectDir <project> -Json
powershell -NoProfile -ExecutionPolicy Bypass -File <runtime>\skills\project-bootstrap\scripts\memory_upgrade.ps1 -ProjectDir <project> -Mode Analyze
powershell -NoProfile -ExecutionPolicy Bypass -File <runtime>\skills\project-context-gate\scripts\context_gate.ps1 -ProjectRoot <project>
powershell -NoProfile -ExecutionPolicy Bypass -File <runtime>\skills\memory-governance\scripts\memory_diagnose.ps1 -ProjectRoot <project>
```

The runtime does not automatically rewrite project memory.

### Skill bridge action

Ordinary installation never writes an agent-specific skill directory. After a
copy-mode runtime install, bridge only the skills and client directory you have
verified:

```powershell
pwsh -NoProfile -File .\scripts\link-agent-skills.ps1 `
  -RuntimeDir <runtime> `
  -AgentSkillsDir <agent-skills-dir> `
  -Skill project-bootstrap,project-context-gate
```

The bridge rejects source checkouts, development-link runtimes, ownership
conflicts, unsafe containment, broken links, and cycles. It establishes
filesystem discovery only; it does not claim full client compatibility.

## Highlights

- **Copy-first runtime and schema 2**: independent installed copies, per-file
  source/installed hashes, incremental refresh, unknown-file preservation,
  local modification conflicts, and explicit schema-1 migration. (#219 / PR
  #230)
- **Explicit agent skill bridge**: installed-copy ownership, canonical path and
  physical ancestor safety, transactional preflight/rollback, and separate
  local metadata. (#220 / PR #231)
- **Candidate intake**: local candidate inbox, read-only discovery and triage,
  public-safe export, deduplication, and no automatic promotion. (#222 / PR
  #232)
- **Session learning trigger**: project-agent delivery guidance now notices
  corrections, validation redo, scope drift, skipped acceptance, and tool
  workarounds while requiring user confirmation for writes. (#225 / PR #233)
- **Directory index diagnostics**: opt-in health checks, deterministic fixtures,
  a reusable index reference, and one public pilot. (#217 / PRs #234-#235)
- **Experience search correctness**: public-safe metadata, localized value
  compatibility, multiline keyword preservation, and stable score ordering on
  PowerShell 7 and Windows PowerShell 5.1. (#221 / #223 / #236 / #238; PRs
  #228 / #229 / #237 / #239)

## Breaking and compatibility notes

- The normal installation strategy is now `copy`; source-linked development
  installs require explicit `-DevLink`.
- Schema-1 copy runtime differences now fail conservatively until the user
  reviews them and chooses `-ReplaceManaged`.
- Existing project memory does not require an automatic or forced migration.
- Candidate intake, the agent skill bridge, and directory index scanning remain
  explicit opt-in surfaces.
- This release does not add an online updater, background project scanning,
  automatic project rewriting, automatic knowledge promotion/decay, or a new
  cross-agent session store.

## Known limitations

- The bridge does not auto-detect client directories or validate every client
  runtime feature.
- Installed-copy knowledge hubs are ordinary runtime directories, so hub lock
  inspection can report `hub_not_git`; use memory analysis and diagnosis for
  project-content checks.
- Full selective uninstall reporting remains deferred.
- #132 remains needs-human; #156 and #211 remain deferred and do not block this
  release. Current `main` contains no tracked `pyproject.toml` or backend value
  matching #156.

## Rollback

- If a runtime refresh reports conflicts, keep the existing runtime and inspect
  `install-report.json`; do not use `-ReplaceManaged` until local changes have
  been reviewed or backed up.
- The previous `v0.5.2` release remains available for source checkout and fresh
  isolated installation.
- Project memory is not automatically rewritten by runtime installation, so a
  runtime rollback does not require a project scaffold rollback.

## Release boundary

This release contains only public-safe repository content. It excludes local
overlay/runtime state and does not change repository settings, rulesets,
branch protection, tag automation, or GitHub Release publication automation.
