## 中文

`v0.5.0` 是一个稳定化 / 治理 / 验证基础设施版本。它打包 `v0.4.6`
之后已经合入 `main` 的公开变更，重点是发布前治理闭环、维护记录边界、
release validator 模块化、旧版本升级演练、Claude Code 采用入口、agent issue
triage hardening，以及 agent-authored PR 的托管身份门禁。

### 主要变更

- 发布前治理与维护边界：定义 v0.5.0 stabilization-first maintenance scope，停止把
  public root `docs/specs/**` 作为公开维护台账，并把公开仓库维护状态路由到 GitHub
  issues、PR bodies、release docs 和治理文档。（#120 / PR #129，#127 / PR #128）
- 工作流内核维护性：明确 `project-bootstrap` command ownership boundary，新增
  `project-context-gate -Brief` 输出，记录 runtime adoption bridge，并完成 PowerShell
  helper ownership closeout。（#119 / PR #130，#117 / PR #133，#116 / PR #131，
  #97 / PR #134 / PR #135）
- Release validator 模块化：抽取 release test helper，拆分 check groups，移动
  workflow-spec-lite validator fixtures，并拆分 language migration mode handlers，为后续验证
  维护降低风险。（#96 / PR #136 / PR #137 / PR #138 / PR #139 / PR #140）
- 旧版本升级路径：记录 old-release upgrade support matrix，并完成 `v0.4.6` 到当前
  `main` 的升级演练证据，覆盖 runtime install upgrade、project memory analyze、hub
  lock drift、context gate 和 memory diagnosis。（#118 / PR #141）
- Claude Code 采用入口：新增 bootstrap-provided `CLAUDE.md` shim，使项目可用
  `@AGENTS.md` 形式把 Claude Code 引导到同一项目入口。（#142 / PR #144）
- Agent issue triage hardening：增强 label sync、maintainer `/decision` command、body
  hygiene 和缺失 Human Triage Decision section 时的收敛行为。（#121 / PR #122，
  #123 / PR #124，#125 / PR #126，#143 / PR #147）
- Agent PR 身份门禁：新增托管 `PR identity guard`，对明确 agent-authored PR 扫描所有
  commits，并验证 author / committer 均为 `agent-ecosystem-bot[bot]`。（#145 / PR #148）

### 验证结果

- 发布前本地 release validation 通过：
  `PASS=58 FAIL=0 WARN=0 DEFERRED=0`。
- `v0.5.0` publish-finalization validation 使用：
  `pwsh -NoProfile -File scripts/validate-release.ps1 -TargetVersion v0.5.0`。
- Hosted Release validation、PR base guard 和 PR identity guard 在 publish-finalization
  PR 上通过后，维护者可直接基于合并后的 `main` 创建 tag 并发布 GitHub Release。

### 升级 / 使用影响

- 对现有安装者没有强制迁移要求。
- `minimal`、`recommended`、`full`、`dev` profile 行为没有变化；`full` 和 `dev`
  仍保留为未来 public domain pack / developer tooling scope。
- `v0.4.6` 到当前 `main` 的演练显示项目记忆结构和模板 hash 兼容，无需迁移步骤。
- 新增 `CLAUDE.md` shim、triage hardening 和 PR identity guard 是治理与采用入口增强，
  不改变已安装 runtime 的核心使用方式。

### 已知限制

- #132 runtime state bridge proposal 仍为长期开放提案，不属于本版本 blocker。
- 本版本不新增 public domain packs，不改变 install profile 行为，不添加 Bash / Zsh wrappers，
  不修改 repository settings / rulesets / secrets。
- Bot identity guard 对明确 agent-authored PR 生效；human-authored PR 不受 bot commit
  metadata 要求影响。显式 Actor Boundary 例外需维护者审查。

### 风险 / 回滚

- 风险集中在文档、治理 workflow 和 release validator 维护面；用户 runtime 兼容风险较低。
- 如 PR identity guard 或 triage automation 需要调整，维护者可通过后续治理 PR 修改
  workflow helper、测试和文档。
- 如发布文本需要修正，维护者可在 GitHub Release body 中进行 body-only 修订，或通过后续
  docs PR 同步 release notes。

## English

`v0.5.0` is a stabilization / governance / validation-infrastructure release.
It packages public changes already merged to `main` after `v0.4.6`, focused on
pre-release governance closure, maintenance-record boundaries, release validator
modularization, old-release upgrade rehearsal evidence, Claude Code adoption,
agent issue triage hardening, and hosted identity checks for agent-authored PRs.

### Highlights

- Pre-release governance and maintenance boundaries: defined the v0.5.0
  stabilization-first maintenance scope, stopped tracking public root
  `docs/specs/**` as repository maintenance state, and routed public maintenance
  records to GitHub issues, PR bodies, release docs, and governance docs.
  (#120 / PR #129, #127 / PR #128)
- Workflow Kernel maintainability: clarified the `project-bootstrap` command
  ownership boundary, added `project-context-gate -Brief`, recorded the runtime
  adoption bridge, and closed out PowerShell helper ownership documentation.
  (#119 / PR #130, #117 / PR #133, #116 / PR #131, #97 / PR #134 / PR #135)
- Release validator modularization: extracted release test helpers, split check
  groups, moved workflow-spec-lite validator fixtures, and split language
  migration mode handlers to reduce maintenance risk. (#96 / PR #136 / PR #137 /
  PR #138 / PR #139 / PR #140)
- Old-release upgrade path: documented the support matrix and recorded the
  `v0.4.6` to current `main` rehearsal evidence, covering runtime install
  upgrade, project memory analyze, hub lock drift, context gate, and memory
  diagnosis. (#118 / PR #141)
- Claude Code adoption: added the bootstrap-provided `CLAUDE.md` shim so
  projects can route Claude Code through the same project entrypoint with
  `@AGENTS.md`. (#142 / PR #144)
- Agent issue triage hardening: strengthened label sync, maintainer
  `/decision` commands, body hygiene, and convergence when the Human Triage
  Decision section is missing. (#121 / PR #122, #123 / PR #124, #125 / PR #126,
  #143 / PR #147)
- Agent PR identity guard: added the hosted `PR identity guard`, scanning every
  commit in explicitly agent-authored PRs and requiring both author and committer
  to be `agent-ecosystem-bot[bot]`. (#145 / PR #148)

### Validation

- Pre-publication local release validation passed:
  `PASS=58 FAIL=0 WARN=0 DEFERRED=0`.
- `v0.5.0` publish-finalization validation uses:
  `pwsh -NoProfile -File scripts/validate-release.ps1 -TargetVersion v0.5.0`.
- After hosted Release validation, PR base guard, and PR identity guard pass on
  the publish-finalization PR, the maintainer can tag and publish directly from
  the merged `main` commit.

### Upgrade / Usage Impact

- Existing installations do not need a forced migration.
- `minimal`, `recommended`, `full`, and `dev` profile behavior is unchanged;
  `full` and `dev` remain reserved for future public domain-pack / developer
  tooling scope.
- The `v0.4.6` to current `main` rehearsal shows compatible project memory
  structure and template hashes, with no migration steps needed.
- The new `CLAUDE.md` shim, triage hardening, and PR identity guard improve
  governance and adoption surfaces without changing the core installed runtime
  workflow.

### Known Limitations

- #132, the runtime state bridge proposal, remains a long-term open proposal and
  is not a blocker for this release.
- This release does not add public domain packs, change install profile
  behavior, add Bash / Zsh wrappers, or modify repository settings, rulesets, or
  secrets.
- The bot identity guard applies to explicitly agent-authored PRs; human-authored
  PRs are not subject to bot commit metadata requirements. Explicit Actor
  Boundary exceptions require maintainer review.

### Risk / Rollback

- Risk is concentrated in documentation, governance workflows, and release
  validator maintainability; user-runtime compatibility risk is low.
- If PR identity guard or triage automation needs adjustment, maintainers can
  update the workflow helper, tests, and docs through a follow-up governance PR.
- If release text needs correction, maintainers can make a body-only GitHub
  Release edit or synchronize the release notes through a follow-up docs PR.
