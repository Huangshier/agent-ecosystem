## 中文

`v0.8.0` 将 `v0.7.1` 之后的 C3.3 实现与一次性的 default / recommended runtime
cutover 收敛为新的版本基线。它确立了以 `project-bootstrap` 与 `project-workspace`
为 active Runtime authority 的工作区模型，为既有项目提供受保护的
Analyze → Apply → Rollback 迁移路径，并验证了从 `v0.7.1` 的旧版 Runtime 与旧版
项目工作区到当前 C3.3 基线的升级路径。

### 谁适合更新

- 使用受管 Runtime、`install.ps1`、`status.ps1` 或 skill bridge 的现有用户。
- 拥有 `v0.7.1` 及更早版本创建的项目工作区，希望迁移到 canonical Work /
  Context / Procedure / Spec 模型的维护者。
- 依赖可审计、public-safe 的 release rehearsal 与验证证据的贡献者。
- 新用户应直接使用当前 C3.3 基线开始。

### 必要升级动作

从检出的 `v0.8.0` source 运行普通安装命令：

```powershell
pwsh -NoProfile -NonInteractive -File .\scripts\install.ps1 -Profile recommended
```

`v0.7.1` 及更早的 schema-2 copy runtime 可通过同一普通默认路径直接增量更新，
不需要 `-ReplaceManaged` 或其 deprecated 兼容别名。安装后可用只读 status 检查
runtime、受管文件、bridge 与项目状态：

```powershell
pwsh -NoProfile -NonInteractive -File <runtime>\scripts\status.ps1 -RuntimeDir <runtime> -ProjectDir <project> -Json
```

#### 旧版 skill bridge 的升级

`v0.7.1` 及更早版本创建的 agent skill bridge 可能包含已从当前 C3.3 Runtime
retired 的 Skills（`project-context-gate`、`workflow-spec-lite`、
`memory-governance`）。升级后 `status.ps1` 会把它们报告为 `stale`，这是预期的
transition 状态；不要手工删除 client 目录中的链接或 bridge manifest 来"修复"
它。要干净地离开该状态，按以下顺序执行：

1. 卸载旧 runtime（会安全移除 manifest-owned 的 stale 链接与 bridge manifest，
   不会删除 client 目录中的其他内容）：

```powershell
pwsh -NoProfile -NonInteractive -File <runtime>\scripts\uninstall.ps1 -TargetDir <runtime> -Json
```

2. 重新安装当前 runtime：

```powershell
pwsh -NoProfile -NonInteractive -File .\scripts\install.ps1 -Profile recommended -TargetDir <runtime>
```

3. 只重新桥接当前 active Skills（`project-bootstrap`、`project-workspace`）：

```powershell
pwsh -NoProfile -NonInteractive -File <runtime>\scripts\link-agent-skills.ps1 -RuntimeDir <runtime> -AgentSkillsDir <agent-skills-dir> -Skill project-bootstrap,project-workspace
```

完成后再运行 `status.ps1`，bridge 应报告 `current`，且不再包含 retired 记录。

升级 Runtime 后，先对既有项目运行当前只读检查，再决定是否需要项目迁移：

```powershell
pwsh -NoProfile -NonInteractive -File <runtime>\skills\project-workspace\scripts\check-project-workspace.ps1 -ProjectRoot <project> -Json
pwsh -NoProfile -NonInteractive -File <runtime>\skills\project-workspace\scripts\discover-project-assets.ps1 -ProjectRoot <project> -Query <query> -Json
```

如果项目被识别为 legacy，使用 Runtime-level 迁移入口执行 Analyze → review →
explicit Apply，并在需要时 guarded Rollback：

```powershell
pwsh -NoProfile -NonInteractive -File <runtime>\scripts\migrate-project.ps1 -Mode Analyze -ProjectRoot <project> -Json
pwsh -NoProfile -NonInteractive -File <runtime>\scripts\migrate-project.ps1 -Mode Apply -ProjectRoot <project> -AnalyzeEvidence <evidence> -ConfirmMigration -Json
pwsh -NoProfile -NonInteractive -File <runtime>\scripts\migrate-project.ps1 -Mode Rollback -ProjectRoot <project> -BackupId <backup-id> -ConfirmRollback -Json
```

### 主要变化

- **C3.3 工作区模型**：canonical durable asset 收敛为 Work、Context、Procedure、
  Spec；`project-workspace` 提供只读 check、渐进式 discover 与显式 authoring。
- **Runtime cutover**：一次性的 default / recommended cutover 将 active Runtime
  authority 收敛到 `project-bootstrap` 与 `project-workspace`；`project-context-gate`、
  `workflow-spec-lite`、`memory-governance` 不再是当前 Runtime authority。
- **Legacy 项目迁移**：`scripts/migrate-project.ps1` 提供确定性的 Analyze、
  显式 Apply（创建完整项目级 backup）与 guarded Rollback，并保留 human
  disposition 边界。
- **旧版升级 rehearsal**：从真实 `v0.7.1` tag 验证了 Runtime install refresh、
  managed-content protection、agent skill bridge transition 与 legacy 项目迁移
  的完整路径。

### 兼容性

- Install profiles、PowerShell 命令接口和普通 copy-first 安装方式保持不变。
- PowerShell Core 7.6+ 是当前要求；Windows PowerShell 5.1 不再构成当前 C3.3
  Runtime 的受支持执行面。
- 既有项目不需要强制迁移；迁移保持 Analyze → explicit Apply → guarded Rollback。
- 未识别或 ambiguous 的 legacy 内容保留为 human disposition，不会被自动改写。
- 普通安装仍不会自动写入 agent-specific skill directory；skill bridge 保持显式
  opt-in。
- Retired Skills 不会被重新安装或重新桥接；升级后已有 bridge 的状态通过
  status 可见并 fail closed。

受支持的发布表面已完成验证。

### 已知限制

- 迁移 Analyze 只接受确定性、可复核的 legacy 内容；ambiguous 或 unsupported
  内容需要 human disposition。
- 一次迁移 Apply 只针对当前 Analyze evidence；迁移后对项目工作区的手工变更会
  使后续 Rollback fail closed。
- Rollback 只恢复未变更的已迁移项目；它不会修改 Runtime 安装或合并内容。
- `status` 与 workspace check 提供诊断，不会自动升级 runtime 或项目。

### 回滚

- 保留或重新检出 `v0.7.0` / `v0.7.1` source，并对隔离 runtime 运行普通
  installer。
- 迁移 Apply 创建完整项目级 backup；guarded Rollback 通过 `-BackupId` 将项目
  恢复到迁移前状态，且 backup 在 rollback 后保留。
- 如果 installer 报告本地修改冲突，保留 runtime 并复核 `install-report.json`；
  不要在未备份定制内容时使用替换选项。

### 公开边界

本版本只包含 public-safe 仓库内容与验证产物契约。它不包含本地 runtime / overlay
状态、private 路径、凭据或原始审计日志，也不修改 repository settings、rulesets、
branch protection、runner、tag automation 或 GitHub Release publication automation。

## English

`v0.8.0` publishes the C3.3 implementation and the one-time default / recommended
runtime cutover merged after `v0.7.1` as the next version baseline. It
establishes the workspace model with `project-bootstrap` and
`project-workspace` as the active Runtime authority, provides a protected
Analyze → Apply → Rollback migration path for existing projects, and verifies
the upgrade path from the `v0.7.1` runtime and project workspace to the current
C3.3 baseline.

### Who this release is for

- Existing users of managed runtimes, `install.ps1`, `status.ps1`, or the skill
  bridge.
- Maintainers with project workspaces created by `v0.7.1` or earlier who want to
  migrate to the canonical Work / Context / Procedure / Spec model.
- Contributors who rely on auditable, public-safe release rehearsals and
  validation evidence.
- New users should start directly from the current C3.3 baseline.

### Required upgrade actions

From the checked-out `v0.8.0` source, run the ordinary installation command:

```powershell
pwsh -NoProfile -NonInteractive -File .\scripts\install.ps1 -Profile recommended
```

A `v0.7.1` (or earlier) schema-2 copy runtime updates incrementally through the
same ordinary default path without `-ReplaceManaged` or its deprecated
compatibility alias. After installation, use read-only status to inspect the
runtime, managed files, bridge, and project state:

```powershell
pwsh -NoProfile -NonInteractive -File <runtime>\scripts\status.ps1 -RuntimeDir <runtime> -ProjectDir <project> -Json
```

#### Upgrading an older skill bridge

An agent skill bridge created by `v0.7.1` or earlier may include Skills that are
retired from the current C3.3 Runtime authority (`project-context-gate`,
`workflow-spec-lite`, `memory-governance`). After upgrade, `status.ps1` reports
them as `stale`, which is the expected transition state; do not manually delete
links or the bridge manifest in the client directory to "fix" it. To leave the
transition state cleanly, run the following in order:

1. Uninstall the old runtime (this safely removes manifest-owned stale links and
   the bridge manifest, and never touches unrelated content in the client
   directory):

```powershell
pwsh -NoProfile -NonInteractive -File <runtime>\scripts\uninstall.ps1 -TargetDir <runtime> -Json
```

2. Reinstall the current runtime:

```powershell
pwsh -NoProfile -NonInteractive -File .\scripts\install.ps1 -Profile recommended -TargetDir <runtime>
```

3. Re-bridge only the current active Skills (`project-bootstrap`,
   `project-workspace`):

```powershell
pwsh -NoProfile -NonInteractive -File <runtime>\scripts\link-agent-skills.ps1 -RuntimeDir <runtime> -AgentSkillsDir <agent-skills-dir> -Skill project-bootstrap,project-workspace
```

Afterwards, `status.ps1` reports the bridge as `current` with no retired records.

After upgrading the runtime, run the current read-only checks against existing
projects before deciding whether project migration is needed:

```powershell
pwsh -NoProfile -NonInteractive -File <runtime>\skills\project-workspace\scripts\check-project-workspace.ps1 -ProjectRoot <project> -Json
pwsh -NoProfile -NonInteractive -File <runtime>\skills\project-workspace\scripts\discover-project-assets.ps1 -ProjectRoot <project> -Query <query> -Json
```

If a project is identified as legacy, use the Runtime-level migration entrypoint
for Analyze → review → explicit Apply, and guarded Rollback when needed:

```powershell
pwsh -NoProfile -NonInteractive -File <runtime>\scripts\migrate-project.ps1 -Mode Analyze -ProjectRoot <project> -Json
pwsh -NoProfile -NonInteractive -File <runtime>\scripts\migrate-project.ps1 -Mode Apply -ProjectRoot <project> -AnalyzeEvidence <evidence> -ConfirmMigration -Json
pwsh -NoProfile -NonInteractive -File <runtime>\scripts\migrate-project.ps1 -Mode Rollback -ProjectRoot <project> -BackupId <backup-id> -ConfirmRollback -Json
```

### Main changes

- **C3.3 workspace model**: canonical durable assets converge to Work, Context,
  Procedure, and Spec; `project-workspace` provides read-only checks, progressive
  discovery, and explicit authoring.
- **Runtime cutover**: the one-time default / recommended cutover converges the
  active Runtime authority to `project-bootstrap` and `project-workspace`;
  `project-context-gate`, `workflow-spec-lite`, and `memory-governance` are no
  longer current Runtime authority.
- **Legacy project migration**: `scripts/migrate-project.ps1` provides
  deterministic Analyze, explicit Apply with a complete project-owned backup, and
  guarded Rollback, preserving the human-disposition boundary.
- **Old-release upgrade rehearsal**: the full upgrade path was verified from the
  real `v0.7.1` tag, covering runtime install refresh, managed-content
  protection, agent skill bridge transition, and legacy project migration.

### Compatibility

- Install profiles, PowerShell command interfaces, and ordinary copy-first
  installation remain unchanged.
- PowerShell Core 7.6+ is the current requirement; Windows PowerShell 5.1 is no
  longer a supported execution surface for the current C3.3 runtime.
- Existing projects do not require forced migration; migration remains Analyze →
  explicit Apply → guarded Rollback.
- Unrecognized or ambiguous legacy content remains a human-disposition finding
  and is not automatically rewritten.
- Ordinary installation still does not write agent-specific skill directories;
  the bridge remains explicit and opt-in.
- Retired Skills are not reinstalled or re-bridged; post-upgrade bridge state is
  visible through status and fails closed.

Validation completed successfully for the supported release surface.

### Known limitations

- Migration Analyze accepts only deterministic, reviewable legacy content;
  ambiguous or unsupported content requires human disposition.
- A migration Apply is bound to the current Analyze evidence; manual edits to a
  project workspace after migration make later Rollback fail closed.
- Rollback restores only an unchanged migrated project; it does not modify the
  runtime installation or merge content.
- `status` and the workspace check provide diagnosis; they do not automatically
  upgrade a runtime or project.

### Rollback

- Keep or re-check out the `v0.7.0` / `v0.7.1` source and run its ordinary
  installer against an isolated runtime.
- A migration Apply creates a complete project-owned backup; guarded Rollback
  restores the project to its pre-migration state by `-BackupId`, and the backup
  is retained after rollback.
- If the installer reports local-modification conflicts, preserve the runtime and
  inspect `install-report.json`; do not use replacement options before customized
  content is backed up.

### Public boundary

This release contains only public-safe repository content and validation artifact
contracts. It excludes local runtime or overlay state, private paths,
authentication material, and raw audit logs, and it does not change repository
settings, rulesets, branch protection, runners, tag automation, or GitHub Release
publication automation.
