# v0.4.5 Release Notes (candidate)

Status: **release-prep candidate** — not yet tagged or published.

This document describes a candidate release. It will become a published
release note only after maintainer authorization, tag creation, and GitHub
Release publication. Do not treat this candidate as a published version.

## Included Changes (post-v0.4.4)

- Issue triage label-sync idempotency: fixed concurrent `issues` event
  handling so label removal no longer fails when a label is already absent.
  (Issue #102, PR #104)
- Spec validator zh-CN anchors: aligned the workflow-spec-lite validator
  with Simplified Chinese heading anchors so zh-CN spec fixtures validate
  correctly. (Issue #94, PR #105)
- UTF-8 no-BOM validator handling: fixed `validate_spec` UTF-8 detection
  for files saved without a BOM, preventing false validator failures on
  zh-CN spec files. (Issue #106, PR #107)
- Release validation workflow permissions: added an explicit minimal
  `permissions` block to `.github/workflows/release-validation.yml`
  (`contents: read`, `actions: write`) to make the CI security boundary
  explicit. (Issue #95, PR #108)
- General issue templates: added `bug-report.md` and
  `feature-request.md` templates alongside the existing
  `agent-candidate.md`, making non-agent issue intake clearer without
  weakening agent-candidate workflow. (Issue #99, PR #109)
