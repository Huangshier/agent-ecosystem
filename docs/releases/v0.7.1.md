## 中文

`v0.7.1` 发布 `v0.7.0` 之后已经合入的维护、修复和验证可靠性改进。它收紧了
bootstrap 与 managed-copy runtime 的状态事实，恢复了项目模板中的全局经验发现指南，
为 context gate 增加确定性的 metadata 查询，并让本地与 hosted 验证更准确地绑定实际
变更和合并候选。

### 谁适合更新

- 使用 copy runtime、hub lock 或 status 判断项目模板来源与一致性的现有用户。
- 需要在进入项目时按 Summary / Keywords 确定性发现相关 context metadata 的维护者。
- 依赖跨平台 release validation、PowerShell 5.1 和可审计候选证据的贡献者。
- 新用户应直接从 `v0.7.1` 开始。

### 必要升级动作

从检出的 `v0.7.1` tag 运行普通安装命令：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install.ps1 -Profile recommended
```

`v0.7.0` schema-2 copy runtime 可通过同一命令直接增量更新，不需要
`-ReplaceManaged`。安装后可用只读 status 检查 runtime、受管文件、bridge 与项目状态：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File <runtime>\scripts\status.ps1 -RuntimeDir <runtime> -ProjectDir <project> -Json
```

若 context gate 报告 `optional-refresh`，先复核本地定制，再显式接受保守刷新：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File <runtime>\skills\project-context-gate\scripts\context_gate.ps1 -ProjectRoot <project>
powershell -NoProfile -ExecutionPolicy Bypass -File <runtime>\skills\project-bootstrap\scripts\bootstrap_project.ps1 -ProjectDir <project> -RefreshUnmodifiedTemplates
```

不要为了获得新模板而覆盖已定制文件。刷新只更新仍匹配可信旧模板基线的文件，并为变更
创建备份。

### 主要变化

- **Runtime、bootstrap 与状态事实修复**：显式传入但不是 knowledge-hub root 的现有
  非空 `HubDir` 会在写入前失败；经 manifest、路径和受管 hash 验证的 managed-copy
  hub 可安全使用 legacy Git lock baseline；status 将 snapshot consistency、source
  provenance 与 remote-latest 状态作为互不覆盖的附加事实报告。
- **项目模板与 context metadata**：新项目模板恢复双语 Global Experience Discovery
  指南；context gate 增加可选 `-Query`，只匹配 `.agents/context/` 条目的 Summary / Keywords
  metadata，并返回确定性、只读、fail-soft 的匹配证据。匹配不表示正文已加载、已应用或
  已获得写入授权。
- **本地与 hosted 验证可靠性**：classifier 统一生成本地 validation plan；Tier 3 和
  affected validation 按 suite / host 分片；exact merge candidate、generation-atomic
  evidence 与 main lineage shadow 收紧候选绑定；合并前恢复非 ASCII PowerShell 编码
  检查，并让 PR 新增行扫描与全仓敏感扫描共用同一规则契约。

### 兼容性

- Install profiles、PowerShell 命令接口和普通 copy-first 安装方式保持不变。
- Windows PowerShell 5.1 继续受支持；PowerShell 7+ 的跨平台使用方式不变。
- 既有项目不需要强制迁移；模板刷新仍为显式、保守且 backup-first 的选择。
- 已定制模板不会被 `-RefreshUnmodifiedTemplates` 覆盖。
- 普通安装仍不会自动写入 agent-specific skill 目录；skill bridge 保持显式 opt-in。
- `status` 新事实是附加字段；既有项目状态和 reason 语义保持兼容。
- `-Query` 是可选参数；未传入时 context gate 的既有使用方式保持不变。

受支持的发布表面已完成验证。

### 已知限制

- Status 与 context gate 只提供诊断、metadata 匹配和建议，不会自动升级 runtime 或项目。
- `remote_latest` 离线保持 `not-checked`；它不会声称已查询或推断远端最新版。
- Context metadata 匹配不搜索正文，也不会自动打开或应用匹配条目。
- Bridge 不会自动探测 client 目录，也不声明每个 client 的完整 runtime 兼容性。
- Bash / Zsh wrapper、后台项目扫描和自动项目改写仍不在本版本范围内。

### 回滚

- 保留或重新检出 `v0.7.0` source，并从该 checkout 对隔离 runtime 运行普通安装器。
- 若 installer 报告本地修改冲突，保留 runtime 并复核 `install-report.json`；不要在未备份
  定制内容时使用替换选项。
- 项目模板刷新会创建备份。若需撤回已接受的模板变化，从对应项目备份恢复；runtime
  回滚不会自动改写项目记忆。

### 公开边界

本版本只包含 public-safe 仓库内容与验证产物契约。它不包含本地 runtime / overlay
状态、private 路径、凭据或原始审计日志，也不修改 repository settings、rulesets、
branch protection、runner、tag automation 或 GitHub Release publication automation。

## English

`v0.7.1` publishes the maintenance, fix, and validation-reliability work already
merged after `v0.7.0`. It tightens bootstrap and managed-copy runtime state
facts, restores global-experience guidance in project templates, adds
deterministic context metadata queries, and binds local and hosted validation
more precisely to actual changes and merge candidates.

### Who this release is for

- Existing users who rely on copy runtimes, hub locks, or status to inspect
  project-template source and consistency.
- Maintainers who want deterministic Summary / Keywords context metadata
  discovery when entering a project.
- Contributors who depend on cross-platform release validation, Windows
  PowerShell 5.1, and auditable candidate evidence.
- New users should start directly from `v0.7.1`.

### Required upgrade actions

From the checked-out `v0.7.1` tag, run the ordinary installation command:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install.ps1 -Profile recommended
```

A `v0.7.0` schema-2 copy runtime updates incrementally with the same command and
does not require `-ReplaceManaged`. After installation, use read-only status to
inspect the runtime, managed files, bridge, and project state:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File <runtime>\scripts\status.ps1 -RuntimeDir <runtime> -ProjectDir <project> -Json
```

If the context gate reports `optional-refresh`, review local customization before
explicitly accepting the conservative refresh:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File <runtime>\skills\project-context-gate\scripts\context_gate.ps1 -ProjectRoot <project>
powershell -NoProfile -ExecutionPolicy Bypass -File <runtime>\skills\project-bootstrap\scripts\bootstrap_project.ps1 -ProjectDir <project> -RefreshUnmodifiedTemplates
```

Do not overwrite customized files just to obtain newer templates. Refresh updates
only files that still match a trusted old template baseline and creates backups
for changed files.

### Main changes

- **Runtime, bootstrap, and state-fact fixes**: an explicitly supplied existing,
  non-empty `HubDir` that is not a knowledge-hub root now fails before writes;
  managed-copy hubs verified through the manifest, path ownership, and managed
  hashes can safely use legacy Git lock baselines; status reports snapshot
  consistency, source provenance, and remote-latest state as separate additive
  facts.
- **Project templates and context metadata**: new project templates restore the
  bilingual Global Experience Discovery guidance; the context gate adds optional
  `-Query` matching over `.agents/context/` Summary / Keywords metadata with
  deterministic, read-only, fail-soft evidence. A match does not mean content was
  loaded, applied, or authorized for writing.
- **Local and hosted validation reliability**: the classifier owns local
  validation plans; Tier 3 and affected validation are sharded by suite and host;
  exact merge candidates, generation-atomic evidence, and the main lineage shadow
  tighten candidate binding; pre-merge non-ASCII PowerShell encoding checks are
  restored; and PR added-line scanning shares one sensitive-scan contract with
  repository-wide validation.

### Compatibility

- Install profiles, PowerShell command interfaces, and ordinary copy-first
  installation remain unchanged.
- Windows PowerShell 5.1 remains supported, and PowerShell 7+ cross-platform use
  is unchanged.
- Existing projects do not require forced migration; template refresh remains
  explicit, conservative, and backup-first.
- Customized templates are not overwritten by `-RefreshUnmodifiedTemplates`.
- Ordinary installation still does not write agent-specific skill directories;
  the bridge remains explicit and opt-in.
- New status facts are additive; existing project status and reason semantics
  remain compatible.
- `-Query` is optional; existing context-gate usage is unchanged when it is not
  supplied.

Validation completed successfully for the supported release surface.

### Known limitations

- Status and the context gate provide diagnosis, metadata matches, and guidance;
  they do not automatically upgrade a runtime or project.
- `remote_latest` remains `not-checked` offline and does not claim to query or
  infer the newest remote revision.
- Context metadata matching does not search entry bodies or automatically open or
  apply matched entries.
- The bridge does not auto-detect client directories or claim complete runtime
  compatibility for every client.
- Bash or Zsh wrappers, background project scanning, and automatic project
  rewriting remain outside this release.

### Rollback

- Keep or re-check out the `v0.7.0` source and run its ordinary installer against
  an isolated runtime.
- If the installer reports local-modification conflicts, preserve the runtime and
  inspect `install-report.json`; do not use replacement options before customized
  content is backed up.
- Project template refresh creates backups. Restore the relevant project backup
  to undo accepted template changes; a runtime rollback does not automatically
  rewrite project memory.

### Public boundary

This release contains only public-safe repository content and validation artifact
contracts. It excludes local runtime or overlay state, private paths,
authentication material, and raw audit logs, and it does not change repository settings, rulesets, branch
protection, runners, tag automation, or GitHub Release publication automation.
