# v0.4.0 Release Notes

Status: public release

`v0.4.0` delivers the conservative `en` / `zh-CN` engineering-memory language
migration workflow. Issue #30 is complete: both Phase 1 (deterministic scaffold
migration) and Phase 2 (narrative migration from manual-review artifacts) are
shipped, validated, and merged.

## Highlights

- Conservative language migration supports both `en` to `zh-CN` and `zh-CN` to
  `en` directions.
- The workflow is proposal-first, backup-first, reviewable, and validate-able.
- Phase 1 replaces exact source-template matches with target-language templates
  and routes customized project content to manual-review sections or artifacts.
- Phase 2 reads retained manual-review artifacts and generates a second
  narrative proposal that routes stable facts, active plan, process state,
  reusable lessons, and durable specs to the correct target-language
  engineering-memory surfaces.
- Narrative actions are unapproved by default; reviewers approve or edit the
  draft text before apply.
- Commands, paths, API names, filenames, commit types, raw errors, and code
  symbols remain in their original form.
- Hot memory files stay concise: source content is routed to migration artifacts
  instead of being inflated back into hot memory.
- The release validator now covers conservative language migration fixtures for
  both directions, mixed memory, project-specific preservation, proposal-first
  apply, backup-first apply, and narrative migration routing.

orchestration framework, or universal workflow bundle.
