## 中文

`v0.4.6` 是一个文档 / 治理 / 发布卫生补丁版本。它打包 `v0.4.5`
之后已经合入 `main` 的公开变更，重点是 spec 生命周期治理、public-safe
知识模式沉淀，以及 GitHub Release 正文与内部发布记录的边界修复。

### 主要变更

- Spec 生命周期与 review 状态治理：新增 `docs/spec-lifecycle.md`，明确
  `docs/specs/**` 工作包的状态生命周期、归档规则、agent 更新卫生和验证期望；
  同时把一个历史 `Completed` 状态归一为 `Done`，并把文档入口加入 README。
  （#98 / PR #111）
- Public-safe 可复用知识模式：新增 staged refactor execution、issue
  decomposition、error diagnosis framing 三个公开安全的 knowledge patterns，
  并登记到 knowledge hub catalog。prompt-preserving clarification 仍作为后续
  模式沉淀项保留。（#100 / PR #112）
- Release body hygiene：分离可复制的 GitHub Release public body 与 internal
  release record，给 `v0.4.4` / `v0.4.5` release notes 增加显式
  `RELEASE_BODY_START` / `RELEASE_BODY_END` 标记，清理 `v0.2.0` /
  `v0.3.0` 的历史 candidate wording，并让 release validator 防止该类问题回归。
  （#113 / PR #114）

  `PASS=54 FAIL=0 WARN=0 DEFERRED=0`。
- Hosted Release validation 在本 publish-finalization PR 上通过，覆盖 Windows

### 升级 / 使用影响

- `minimal`、`recommended`、`full`、`dev` profile 行为没有变化。
- 新增 knowledge patterns 和 release hygiene 规则不影响已有 runtime 行为。

### 已知限制

- 本版本不处理 validator / language migration 模块化（#96）或 PowerShell helper

- 若 release hygiene wording 需要调整，维护者可通过后续 docs PR 修改对应 release
  notes 和 validator checks。

## English

`v0.4.6` is a documentation / governance / release-hygiene patch release. It
packages public changes already merged to `main` after `v0.4.5`, focused on spec
lifecycle governance, public-safe knowledge pattern capture, and the boundary
between GitHub Release public body text and internal release records.

### Highlights

- Spec lifecycle and review-status hygiene: added `docs/spec-lifecycle.md` to
  define status lifecycle, archival rules, agent update hygiene, and validation
  expectations for `docs/specs/**` work packages; normalized one historical
  `Completed` status to `Done`; and linked the document from both README
  entrypoints. (#98 / PR #111)
- Public-safe reusable knowledge patterns: added staged refactor execution,
  issue decomposition, and error diagnosis framing patterns to the public
  knowledge hub and catalog. Prompt-preserving clarification remains deferred
  for a future pattern pass. (#100 / PR #112)
- Release body hygiene: separated copyable GitHub Release public body text from
  internal release records, added explicit `RELEASE_BODY_START` /
  `RELEASE_BODY_END` markers to `v0.4.4` / `v0.4.5` release notes, cleaned
  historical candidate wording from `v0.2.0` / `v0.3.0`, and hardened the
  release validator against this regression. (#113 / PR #114)

### Validation

- Pre-publication local release validation passed:
  `PASS=54 FAIL=0 WARN=0 DEFERRED=0`.
- Hosted Release validation passed on this publish-finalization PR, covering
  Windows PowerShell 5.1, Windows `pwsh`, Ubuntu `pwsh`, and macOS `pwsh`.

### Upgrade / Usage Impact

- Existing installations do not need a forced migration.
- `minimal`, `recommended`, `full`, and `dev` profile behavior is unchanged.
- New knowledge patterns and release hygiene rules do not affect existing
  runtime behavior.

### Known Limitations

- This release does not address validator / language migration modularization
  (#96) or PowerShell helper ownership (#97).
- This release does not add public domain packs, change install profile
  behavior, or modify repository settings, rulesets, or secrets.

### Risk / Rollback

- Risk is concentrated in documentation, release notes, and validator hygiene
  checks; user-runtime compatibility risk is low.
- If release hygiene wording needs adjustment, maintainers can update the
  relevant release notes and validator checks through a follow-up docs PR.

## Linked Issues and PRs

## Release Boundary

mappings, machine-specific paths, private review material, local-only runtime
memory, repository settings, rulesets, secrets, or branch-protection changes.
