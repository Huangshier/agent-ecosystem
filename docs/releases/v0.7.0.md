## 中文

`v0.7.0` 完成 `v0.6.0` 之后的稳定化收尾。它让 runtime 与项目状态可直接检查，
让 context gate 能主动提示项目模板漂移，并用更清晰的项目契约和用户旅程降低升级、
诊断与维护成本。

### 谁适合更新

- 希望确认 runtime 来源、受管文件、skill bridge 与项目模板状态的现有用户。
- 希望 context gate 在进入旧项目时主动提示安全刷新动作的维护者。
- 需要更明确的根 `AGENTS.md` 权威边界和更精简工程记忆指南的团队。
- 新用户应直接从 `v0.7.0` 开始。

### 必要升级动作

从检出的 `v0.7.0` tag 运行普通安装命令：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install.ps1 -Profile recommended
```

安装后可用只读 status 检查 runtime、受管文件、bridge 与项目状态：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File <runtime>\scripts\status.ps1 -RuntimeDir <runtime> -ProjectDir <project> -Json
```

进入既有项目时，运行 installed context gate。若它报告
`optional-refresh`，先复核项目本地定制，再按提示使用保守刷新：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File <runtime>\skills\project-context-gate\scripts\context_gate.ps1 -ProjectRoot <project>
powershell -NoProfile -ExecutionPolicy Bypass -File <runtime>\skills\project-bootstrap\scripts\bootstrap_project.ps1 -ProjectDir <project> -RefreshUnmodifiedTemplates
```

不要为获得新模板而覆盖已定制文件。刷新命令只更新仍与旧基线一致的模板，并为变更
创建备份。

### 主要变化

- **可验证的 runtime 状态**：schema-2 manifest 记录 source identity、release/commit
  provenance 与逐文件受管状态；status 同时汇总 runtime、managed files、bridge、
  project drift 和确定性下一步。
- **主动项目漂移提示**：installed context gate 使用可信 status provider，在进入旧项目
  时区分 `current`、`optional-refresh`、`migration-required` 与 `unknown`，并保持
  fail-closed。
- **单一项目行为契约**：根 `AGENTS.md` 是唯一权威行为契约；
  `.agents/AGENTS.md` 聚焦工程记忆结构与使用方式。
- **更清晰的采用路径**：中英文 README 按 Release → Runtime → Agent bridge →
  Project 生命周期组织安装、升级、状态检查和常见任务入口。
- **更高效且可审计的验证**：变更按风险路由，固定 validation gate 始终汇总结果；
  完整验证保留跨平台和旧版 PowerShell 覆盖，同时输出 public-safe 的时长、identity、
  coverage 与 artifact 契约。

### 兼容性

- `v0.6.0` schema-2 copy runtime 可通过普通安装命令直接增量更新，不需要
  `-ReplaceManaged`。
- 既有项目不需要强制迁移；项目模板刷新仍是显式、保守且 backup-first 的选择。
- 已定制模板不会被 `-RefreshUnmodifiedTemplates` 覆盖。
- 普通安装仍不自动写入 agent-specific skill 目录；bridge 保持显式 opt-in。
- PowerShell 脚本接口、安装 profiles 和 public Workflow Kernel 定位保持不变。

受支持的发布表面已完成验证。

### 已知限制

- status 与 context gate 提供只读诊断和建议，不会自动升级 runtime 或项目。
- bridge 不会自动探测 client 目录，也不声明每个 client 的完整 runtime 兼容性。
- 项目模板状态依赖可信 installed runtime provenance；证据不足时会报告 `unknown`。
- Bash / Zsh wrapper、后台项目扫描和自动项目改写仍不在本版本范围内。

### 回滚

- 保留或重新检出 `v0.6.0` source，并从该 checkout 对隔离 runtime 运行普通安装器。
- 若 installer 报告本地修改冲突，先保留 runtime 并复核
  `install-report.json`；不要在未备份定制内容时使用替换选项。
- 项目模板刷新会创建备份。若需撤回已接受的模板变化，从对应项目备份恢复；runtime
  回滚不会自动改写项目记忆。

### 公开边界

本版本只包含 public-safe 仓库内容与验证产物契约。它不包含本地 runtime/overlay
状态、private 路径或原始审计日志，也不修改 repository settings、rulesets、branch
protection、runner、tag automation 或 GitHub Release publication automation。

## English

`v0.7.0` completes the stabilization work after `v0.6.0`. Runtime and project
state are directly inspectable, the context gate can proactively report project
template drift, and clearer project contracts and lifecycle documentation reduce
upgrade, diagnosis, and maintenance cost.

### Who this release is for

- Existing users who want to verify runtime source, managed files, skill bridge
  health, and project template state.
- Maintainers who want the context gate to suggest safe refresh actions when
  entering an older project.
- Teams that want a clearer root `AGENTS.md` authority boundary and a smaller
  engineering-memory guide.
- New users should start directly from `v0.7.0`.

### Required upgrade actions

From the checked-out `v0.7.0` tag, run the ordinary installation command:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install.ps1 -Profile recommended
```

After installation, use the read-only status surface to inspect the runtime,
managed files, bridge, and project state:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File <runtime>\scripts\status.ps1 -RuntimeDir <runtime> -ProjectDir <project> -Json
```

When entering an existing project, run the installed context gate. If it
reports `optional-refresh`, review local customization before accepting the
conservative refresh action:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File <runtime>\skills\project-context-gate\scripts\context_gate.ps1 -ProjectRoot <project>
powershell -NoProfile -ExecutionPolicy Bypass -File <runtime>\skills\project-bootstrap\scripts\bootstrap_project.ps1 -ProjectDir <project> -RefreshUnmodifiedTemplates
```

Do not overwrite customized files just to obtain newer templates. The refresh
updates only templates that still match their old baseline and creates a
backup for changed files.

### Main changes

- **Inspectable runtime state**: schema-2 manifests record source identity,
  release/commit provenance, and per-file managed state; status summarizes the
  runtime, managed files, bridge, project drift, and deterministic next actions.
- **Proactive project drift guidance**: the installed context gate uses a
  trusted status provider to distinguish `current`, `optional-refresh`,
  `migration-required`, and `unknown` while remaining fail-closed.
- **One project behavior contract**: root `AGENTS.md` is the sole authoritative
  behavior contract; `.agents/AGENTS.md` focuses on engineering-memory layout
  and use.
- **Clearer adoption path**: the Chinese and English READMEs organize install,
  upgrade, status, and common-task guidance around the Release → Runtime →
  Agent bridge → Project lifecycle.
- **More efficient, auditable validation**: changes are routed by risk and a
  fixed validation gate always summarizes the result; full validation retains
  cross-platform and legacy PowerShell coverage while producing public-safe
  duration, identity, coverage, and artifact contracts.

### Compatibility

- A `v0.6.0` schema-2 copy runtime updates incrementally with the ordinary
  install command and does not require `-ReplaceManaged`.
- Existing projects do not require forced migration; template refresh remains
  an explicit, conservative, backup-first choice.
- Customized templates are not overwritten by
  `-RefreshUnmodifiedTemplates`.
- Ordinary installation still does not write agent-specific skill directories;
  the bridge remains explicit and opt-in.
- PowerShell command interfaces, install profiles, and the public Workflow
  Kernel positioning remain unchanged.

Validation completed successfully for the supported release surface.

### Known limitations

- Status and the context gate provide read-only diagnosis and guidance; they do
  not automatically upgrade a runtime or project.
- The bridge does not auto-detect client directories or claim complete runtime
  compatibility for every client.
- Project template status depends on trusted installed-runtime provenance and
  reports `unknown` when evidence is insufficient.
- Bash or Zsh wrappers, background project scanning, and automatic project
  rewriting remain outside this release.

### Rollback

- Keep or re-check out the `v0.6.0` source and run its ordinary installer
  against an isolated runtime.
- If the installer reports local-modification conflicts, preserve the runtime
  and inspect `install-report.json`; do not use replacement options before
  customized content is backed up.
- Project template refresh creates backups. Restore the relevant project backup
  to undo accepted template changes; a runtime rollback does not automatically
  rewrite project memory.

### Public boundary

This release contains only public-safe repository content and validation
artifact contracts. It excludes local runtime or overlay state, private paths,
and raw audit logs, and it does not change repository settings, rulesets,
branch protection, runners, tag automation, or GitHub Release publication
automation.
