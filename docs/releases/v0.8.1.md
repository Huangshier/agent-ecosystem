## 中文

`v0.8.1` 是 `v0.8.0` 之后的向后兼容 patch Release。它收紧了
`project-workspace` 的日常可靠性和可审计性，让以 `pwsh -File` 驱动的无头
工作流在列表输入、continuity 追加与 package 布局检查上行为一致，并减少
contributor 在本地迭代与推送验证之间重复支付的成本。

### 谁适合更新

- 使用 `project-workspace` 的 `check` / `discover` / continuity 只读与显式
  写入操作的维护者和贡献者。
- 通过 `pwsh -File` 调用工作流内核、依赖稳定列表输入或 checkpoint 追加语义
  的无头（headless）工作流用户。
- 想减少本地 iteration / pre-push 重复验证开销，并依赖按风险面收敛的
  fail-closed 路由的维护者。
- 新用户应直接使用当前 C3.3 基线开始。

### 必要升级动作

不需要强制动作。既是既有 schema-2 copy runtime，可沿普通默认增量安装路径
更新。从检出的 `v0.8.1` source 运行普通安装命令：

```powershell
pwsh -NoProfile -NonInteractive -File .\scripts\install.ps1 -Profile recommended
```

安装后可用只读 status 检查 runtime、受管文件、bridge 与项目状态：

```powershell
pwsh -NoProfile -NonInteractive -File <runtime>\scripts\status.ps1 -RuntimeDir <runtime> -ProjectDir <project> -Json
```

### 主要变化

- **C3.3 workspace 布局校验解耦**：canonical workspace 的有效性不再受可重建
  知识 Catalog 的缺失或过期影响；Catalog 观察项现在只作为 warning 提示，
  而 canonical schema、reference 与 revision 错误仍保持 fail closed。
- **列表输入可靠化**：`project-workspace` 的公开列表参数在 `pwsh -File` 下
  表现一致，支持 `json:` 表达式表达多值或显式空列表，并保留自然语言中的
  逗号；非法结构化数组在写入前以稳定错误失败。
- **Checkpoint 追加 / 替换语义显式化**：continuity 更新新增显式追加与去重，
  并保留整体替换兼容路径，避免调用方在持有最新 revision 时静默丢失既有
  `Verified` / `Boundaries` / `Blockers` 事实。
- **验证开销收敛**：迭代与推送阶段不再重复重放同一批本地验证，未知风险路由
  按风险面收敛为保守 fail-closed 回退，self-protection 收敛为聚焦的
  control-plane oracle。

### 兼容性

- Install profiles、PowerShell 命令接口与普通 copy-first 安装方式保持不变。
- PowerShell Core 7.6+ 仍是当前要求；Windows PowerShell 5.1 不再构成当前
  C3.3 Runtime 的受支持执行面。
- active Runtime authority 仍为 `project-bootstrap` 与 `project-workspace`；
  本版本不改变 default / recommended cutover、install profile 或
  Runtime validation 架构。
- 既有项目不需要强制迁移；legacy 迁移路径保持 Analyze → explicit Apply →
  guarded Rollback。
- 旧的 checkpoint 整体替换参数保持兼容；新增的追加/去重语义是显式扩展，
  不改变既有调用方的默认行为。

受支持的发布表面已完成验证。

### 已知限制

- 列表输入归一化在同一次调用中按单个参数生效；`json:` 表达多值时仍需符合
  稳定 JSON 数组语法。
- checkpoint 追加/去重针对已存在 section 提供保护，不会回填历史上已丢失的
  事实。
- Catalog 观察项作为 warning 提示，不推高为失败；标准 warning 不会让既有
  有效 workspace 被误判为 FAIL。

### 回滚

- 保留或重新检出 `v0.8.0` source，并对隔离 runtime 运行普通 installer。
- 既有 schema-2 copy runtime 可通过普通默认增量路径回到上一版本；受管文件
  的本地定制内容在更新前会被保留并报告冲突。
- 如果 installer 报告本地修改冲突，保留 runtime 并复核 `install-report.json`；
  不要在未备份定制内容时使用替换选项。

### 公开边界

本版本只包含 public-safe 仓库内容与验证产物契约。它不包含本地 runtime /
overlay 状态、private 路径、凭据或原始审计日志，也不修改 repository settings、
rulesets、branch protection、runner、tag automation 或 GitHub Release
publication automation。

## English

`v0.8.1` is a backward-compatible patch release after `v0.8.0`. It tightens
the day-to-day reliability and auditability of `project-workspace` so headless
workflows driven through `pwsh -File` behave consistently for list inputs,
continuity appends, and package-layout checks, and it lowers the cost
contributors pay for duplicated local iteration and push validation.

### Who this release is for

- Maintainers and contributors using `project-workspace` read-only checks,
  discovery, and explicit continuity writes.
- Headless users calling the workflow kernel through `pwsh -File` who depend on
  stable list inputs or explicit checkpoint append semantics.
- Maintainers who want to reduce duplicate local iteration / pre-push validation
  and rely on a fail-closed, risk-surfaced routing fallback.
- New users should start directly from the current C3.3 baseline.

### Required upgrade actions

No forced action is required. Existing schema-2 copy runtimes update through the
ordinary default incremental install path. From the checked-out `v0.8.1` source,
run the ordinary installation command:

```powershell
pwsh -NoProfile -NonInteractive -File .\scripts\install.ps1 -Profile recommended
```

After installation, use read-only status to inspect the runtime, managed files,
bridge, and project state:

```powershell
pwsh -NoProfile -NonInteractive -File <runtime>\scripts\status.ps1 -RuntimeDir <runtime> -ProjectDir <project> -Json
```

### Main changes

- **C3.3 workspace layout validation decoupled**: canonical workspace validity
  no longer depends on a missing or stale rebuildable knowledge Catalog; Catalog
  findings are now warnings while canonical schema, reference, and revision
  errors still fail closed.
- **Reliable list inputs**: `project-workspace` public list parameters behave
  consistently under `pwsh -File`, support a `json:` expression for multiple
  values or an explicit empty list, and preserve commas in natural-language
  values; invalid structured arrays fail before project writes with a stable
  error.
- **Explicit checkpoint append / replace semantics**: continuity updates gain
  explicit append and dedupe while preserving the whole-replace compatibility
  path, avoiding silent loss of existing `Verified` / `Boundaries` / `Blockers`
  facts when a caller holds the latest revision.
- **Converged validation cost**: iteration and pre-push no longer replay the same
  local validation set twice, unknown-risk routing converges to a conservative
  fail-closed fallback by risk surface, and self-protection is a focused
  control-plane oracle.

### Compatibility

- Install profiles, PowerShell command interfaces, and ordinary copy-first
  installation remain unchanged.
- PowerShell Core 7.6+ remains the current requirement; Windows PowerShell 5.1 is
  no longer a supported execution surface for the current C3.3 runtime.
- The active Runtime authority remains `project-bootstrap` and
  `project-workspace`; this release does not change the default / recommended
  cutover, install profiles, or the Runtime validation architecture.
- Existing projects do not require forced migration; the legacy migration path
  remains Analyze → explicit Apply → guarded Rollback.
- The existing whole-replace checkpoint parameter stays compatible; the new
  append / dedupe semantics are an explicit extension and do not change the
  default behavior for existing callers.

Validation completed successfully for the supported release surface.

### Known limitations

- List-input normalization applies per parameter in a single call; expressing
  multiple values through `json:` still requires valid stable JSON array syntax.
- Checkpoint append / dedupe protects existing sections; it does not backfill
  facts already lost historically.
- Catalog findings are surfaced as warnings and do not escalate to failure;
  standard warnings do not misreport an already-valid workspace as FAIL.

### Rollback

- Keep or re-check out the `v0.8.0` source and run its ordinary installer against
  an isolated runtime.
- Existing schema-2 copy runtimes return to the previous version through the
  ordinary default incremental path; locally customized managed content is
  preserved and reported as a conflict before the update.
- If the installer reports local-modification conflicts, preserve the runtime and
  inspect `install-report.json`; do not use replacement options before customized
  content is backed up.

### Public boundary

This release contains only public-safe repository content and validation artifact
contracts. It excludes local runtime or overlay state, private paths,
authentication material, and raw audit logs, and it does not change repository
settings, rulesets, branch protection, runners, tag automation, or GitHub Release
publication automation.
