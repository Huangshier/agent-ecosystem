## 中文

`v0.9.0` 是 `v0.8.0` 之后的 minor Release。它收敛了 `project-workspace`
的日常可靠性与本地验证开销，并让 `project-bootstrap` 在无法确定 workspace
身份时明确失败，而不是静默选择 legacy 身份。

### 谁适合更新

- 使用 `project-workspace` 的 `check` / `discover` / continuity 读写操作的
  维护者、贡献者和无头工作流用户。
- 在既有项目上运行 `project-bootstrap`，需要 workspace 身份选择行为明确、
  可审计的 agent 与维护者。
- 想减少本地 iteration / pre-push 重复验证开销的维护者。
- 新用户应直接使用当前 C3.3 基线开始。

### 必要升级动作

既有 schema-2 copy runtime 沿普通默认增量安装路径更新，从检出的 `v0.9.0`
source 运行：

```powershell
pwsh -NoProfile -NonInteractive -File .\scripts\install.ps1 -Profile recommended
```

安装后可用只读 status 检查 runtime、受管文件、bridge 与项目状态：

```powershell
pwsh -NoProfile -NonInteractive -File <runtime>\scripts\status.ps1 -RuntimeDir <runtime> -ProjectDir <project> -Json
```

一项行为变化需要项目维护者注意：当项目已有 agent memory 但
`.agents/hub.lock.json` 不存在时，bootstrap 现在会在任何写入前失败，不再
静默选择 legacy workspace。该 fail-closed 行为只适用于这种"既有 memory 且
lock 缺失"的模糊目标；空项目与已有 lock 文件的项目行为不变。恢复方式
二选一：

- 从项目自身仓库的可信 Git 历史恢复原 lock：列出
  `git log --oneline --all -- .agents/hub.lock.json`，用
  `git show <revision>:.agents/hub.lock.json` 确认该 revision 记录的项目
  身份属于本项目，且确认当前 `.agents/hub.lock.json` 确实不存在后再恢复；
  bootstrap 不会自动重建 lock，也不会从目录布局推断身份。
- 或显式传 `-LegacyWorkspace` 表达 legacy 选择意图；该参数只在目标确为
  既有 memory 项目时被接受，对空项目或已有 lock 的项目会在写入前被拒绝，
  且不授予任何额外权限。

### 主要变化

- **Workspace 布局校验解耦**：canonical workspace 的有效性不再受可重建
  知识 Catalog 的缺失或过期影响；Catalog 观察项降为 warning，canonical
  schema、reference 与 revision 错误仍保持 fail closed。
- **列表输入可靠化**：`project-workspace` 的公开列表参数在 `pwsh -File`
  下表现一致，支持 `json:` 表达式表达多值或显式空列表；非法结构化数组在
  写入前以稳定错误失败。
- **Checkpoint 追加 / 替换语义显式化**：continuity 更新提供显式追加与
  去重，并保留整体替换兼容路径，避免持有最新 revision 时静默丢失既有
  `Verified` / `Boundaries` / `Blockers` 事实。
- **Workspace 身份 fail closed**：既有 memory 且 lock 缺失的项目上，
  bootstrap 在写入前失败；legacy 选择必须显式声明，并在迁移委托前校验
  适用性。
- **验证开销收敛**：迭代与推送阶段不再重复重放同一批本地验证；未知风险
  路由按风险面收敛为保守 fail-closed 回退；self-protection 收敛为聚焦的
  control-plane oracle。
- C3.3 adoption 文档与公开维护表面在 `v0.8.0` 之后完成了一轮收敛。

### 兼容性

- Install profiles、PowerShell 命令接口、copy-first 安装方式、active
  Runtime authority（`project-bootstrap` + `project-workspace`）、
  PowerShell Core 7.6+ 基线与 default / recommended cutover 保持不变。
- 既有项目不需要强制迁移；legacy 迁移路径保持 Analyze → explicit Apply →
  guarded Rollback。
- "既有 memory 且 lock 缺失"的项目从静默选择 legacy 变为 fail closed；
  调用方需按上文恢复方式显式表达意图。
- canonical workspace 检查中 Catalog 缺失或过期从失败降为 warning；
  canonical schema、reference 与 revision 错误的失败行为不变。
- 旧的 checkpoint 整体替换参数保持兼容；追加/去重是显式扩展，不改变既有
  调用方的默认行为。

受支持的发布表面已完成验证。

### 已知限制

- bootstrap 不会自动恢复丢失的 lock；lock 历史不可信或不存在时，需要项目
  维护者人工决定身份，而不是由 Runtime 推断。
- `-LegacyWorkspace` 只表达选择意图，不绕过任何安全检查；对空项目或已有
  lock 的项目会被拒绝。
- 列表输入归一化在同一次调用中按单个参数生效；`json:` 表达多值仍需符合
  稳定 JSON 数组语法。
- checkpoint 追加/去重针对已存在 section 提供保护，不回填历史上已丢失的
  事实。

### 回滚

- 保留或重新检出 `v0.8.0` source，对隔离 runtime 运行普通 installer。
- 既有 schema-2 copy runtime 可通过普通默认增量路径回到上一版本；受管
  文件的本地定制内容在更新前会被保留并报告冲突。
- 如果 installer 报告本地修改冲突，保留 runtime 并复核
  `install-report.json`；不要在未备份定制内容时使用替换选项。

### 公开边界

本版本只包含 public-safe 仓库内容与验证产物契约。它不包含本地 runtime /
overlay 状态、private 路径、凭据或原始审计日志，也不修改 repository
settings、rulesets、branch protection、runner、tag automation 或 GitHub
Release publication automation。

## English

`v0.9.0` is a minor release after `v0.8.0`. It converges the day-to-day
reliability of `project-workspace` and the local validation cost, and makes
`project-bootstrap` fail explicitly when the workspace identity cannot be
determined instead of silently selecting the legacy identity.

### Who this release is for

- Maintainers, contributors, and headless workflow users of the
  `project-workspace` `check` / `discover` / continuity surfaces.
- Agents and maintainers running `project-bootstrap` on existing projects who
  need explicit, auditable workspace-identity selection.
- Maintainers who want to reduce duplicate local iteration / pre-push
  validation.
- New users should start directly from the current C3.3 baseline.

### Required upgrade actions

Existing schema-2 copy runtimes update through the ordinary default
incremental install path from the checked-out `v0.9.0` source:

```powershell
pwsh -NoProfile -NonInteractive -File .\scripts\install.ps1 -Profile recommended
```

After installation, use read-only status to inspect the runtime, managed
files, bridge, and project state:

```powershell
pwsh -NoProfile -NonInteractive -File <runtime>\scripts\status.ps1 -RuntimeDir <runtime> -ProjectDir <project> -Json
```

One behavior change needs maintainer attention: when a project has existing
agent memory but `.agents/hub.lock.json` does not exist, bootstrap now fails
before any write instead of silently selecting the legacy workspace. This
fail-closed behavior applies only to that ambiguous existing-memory,
missing-lock target; empty projects and projects with an existing lock file
keep their current behavior. Recover in one of two ways:

- Restore the original lock from the project's own trusted Git history: list
  `git log --oneline --all -- .agents/hub.lock.json`, confirm with
  `git show <revision>:.agents/hub.lock.json` that the revision's recorded
  project identity belongs to this project, and confirm the lock is still
  absent before restoring. Bootstrap never auto-restores the lock and never
  infers identity from the directory layout.
- Or pass `-LegacyWorkspace` explicitly. The flag is accepted only for a
  project with existing memory; it is rejected before any write for empty
  projects and for projects that already have a lock file, and it grants no
  additional permissions.

### Main changes

- Workspace layout validation no longer depends on the rebuildable knowledge
  Catalog being present or fresh; Catalog findings are warnings, while
  canonical schema, reference, and revision errors still fail closed.
- `project-workspace` list inputs behave consistently under `pwsh -File`,
  with `json:` expressions for multiple values and explicit empty lists;
  malformed structured arrays fail with a stable error before any write.
- Checkpoint append vs. replace semantics are explicit, with append and
  deduplication alongside the compatible whole-replace path, preventing
  silent loss of existing `Verified` / `Boundaries` / `Blockers` facts.
- Workspace identity fails closed for existing-memory projects with a
  missing lock; legacy selection must be declared explicitly and is
  validated before any migration delegation.
- Local validation no longer replays the same suites between iteration and
  pre-push; unknown-risk routing converges to a conservative fail-closed
  fallback, and self-protection is a focused control-plane oracle.
- C3.3 adoption and public maintenance documentation surfaces were converged
  after `v0.8.0`.

### Compatibility

- Install profiles, the PowerShell command interface, copy-first
  installation, the active Runtime authority (`project-bootstrap` +
  `project-workspace`), the PowerShell Core 7.6+ baseline, and the
  default / recommended cutover are unchanged.
- Existing projects do not need forced migration; the legacy migration path
  remains Analyze → explicit Apply → guarded Rollback.
- Projects with existing memory and a missing lock now fail closed instead
  of silently selecting the legacy workspace; callers must express intent
  through one of the recovery paths above.
- A missing or stale knowledge Catalog in canonical workspace checks is now
  a warning instead of a failure; canonical schema, reference, and revision
  errors still fail closed.
- The old checkpoint whole-replace parameter stays compatible; append and
  dedup are explicit extensions that do not change existing callers'
  default behavior.

Validation completed successfully for the supported release surface.

### Known limitations

- Bootstrap never auto-restores a lost lock; when no trusted lock history
  exists, the project maintainer decides the identity instead of the
  runtime.
- `-LegacyWorkspace` only expresses selection intent and bypasses no safety
  checks; it is rejected for empty projects and projects that already have a
  lock file.
- List-input normalization applies per parameter within one call; `json:`
  multi-values still require stable JSON array syntax.
- Checkpoint append/dedup protects existing sections and does not backfill
  facts lost before this release.

### Rollback

- Keep or re-check out the `v0.8.0` source and run the ordinary installer
  against an isolated runtime.
- Existing schema-2 copy runtimes return to the previous release through the
  ordinary default incremental path; locally customized managed files are
  preserved and reported as conflicts before update.
- If the installer reports local-modification conflicts, keep the runtime and
  review `install-report.json`; do not use the replacement option without
  backing up customizations first.

### Public boundary

This release contains only public-safe repository content and validation
artifact contracts. It excludes local runtime or overlay state, private
paths, authentication material, and raw audit logs, and it does not change
repository settings, rulesets, branch protection, runners, tag automation,
or GitHub Release publication automation.
