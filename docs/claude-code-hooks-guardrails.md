# Claude Code Hooks Guardrails

This document defines the public contract for the first Claude Code hooks
guardrails slice.

The guardrails are for template reliability. They help a project generated by
project-bootstrap keep Claude Code aligned with the existing entrypoint,
project-memory, boundary, and authorization rules. They are not a security
sandbox, a permissions isolation model, or automatic authorization for GitHub
or other external writes. In short: this is not a security sandbox.

## Goals

- Make `CLAUDE.md` the Claude Code adoption surface for project-bootstrap
  projects.
- Ensure generated projects expose a small `.claude/guardrails/` contract that
  Claude Code can load alongside `AGENTS.md` and `.agents/**` memory.
- Require awareness of project language, `AGENTS.md`, `.agents/AGENTS.md`,
  `.agents/process.txt`, `.agents/plan.md`, and `.agents/hub.lock.json` before
  memory refresh, migration, reset, or long-running governance work.
- Keep public/private boundary checks explicit.
- Model external write authority through a write authorization profile instead
  of assuming every project has a bot.
- Preserve ordinary public contributor paths: issues, fork pull requests, CI,
  and maintainer review do not require a bot identity.
- Stop at `needs-human` when context, authority, boundary, or dangerous memory
  refresh confirmation is missing.
- Keep raw artifacts local or private unless a public-safe summary is
  intentionally prepared.

## Non-Goals

- No security sandbox or permission isolation.
- No default GitHub issue, pull request, label, release, tag, merge, repository
  setting, runner, secret, or workflow-dispatch write.
- No replacement for maintainer review or release decisions.
- No requirement that all projects use `agent-ecosystem-bot` or any other bot.
- No blocking of normal external contributor issues, fork pull requests, CI, or
  maintainer review.
- No publication of private raw evidence, transcripts, hook payloads, local
  paths, secrets, or private harness details.

## Default Template Behavior

Project-bootstrap installs a minimal `.claude/guardrails/` tree into generated
projects and imports its README from `CLAUDE.md`.

The default profile is `local-only`. It allows local project work when the user
or project instructions authorize it, and treats external writes as requiring
explicit confirmation. The `public-contributor` profile keeps public
collaboration paths open without a bot requirement. A stricter
`project-maintenance` profile may be declared by a project when it has a
project-specific automation path.

The template profile is declarative. It does not run GitHub writes, create a
GitHub App, create secrets, change repository settings, mark pull requests
ready, merge, tag, or publish releases.

## Agent-Ecosystem Maintenance Profile

This repository has a project-specific automation identity documented in
[Agent Governance](agent-governance.md#automation-identity). For
agent-assisted public maintenance in this repository, branch pushes and pull
request creation use that declared maintenance profile.

That rule is specific to this repository. This repository-specific bot path must not be promoted into the generic project-bootstrap template as a universal bot requirement.

## Deterministic Fixtures

The release validator checks the public contract, the generated template files,
the bundled project-bootstrap snapshot, and the public-safe fixture matrix under
`scripts/validation/claude-hooks-guardrails-fixtures/`.

The fixture matrix covers:

- entry loading;
- project context loading;
- project language, `AGENTS.md`, and `.agents/hub.lock.json` awareness;
- public/private boundary;
- write authorization profiles;
- wrong write path;
- dangerous memory refresh confirmation;
- stop point / `needs-human` outcome;
- raw artifact quarantine;
- public contributor path with no bot requirement.

The fixtures are deterministic public examples. They are not copied raw
evidence from private validation runs.
